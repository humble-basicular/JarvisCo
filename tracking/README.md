# Proof-link tracking contract v1

Independent Cloudflare Worker + D1 for spec §4; no CRM source changes. Deploy owner: parent/integration agent. This contract is committed before implementation so the site and CRM can implement against it.

## Public endpoints

Both `jarvisweb.lt` and `www.jarvisweb.lt` have `/p/*` and `/t/*` Worker routes.

- `GET /p/a2345`: `302 Location: /arboristams?r=a2345`, `Cache-Control: no-store`; records `click`. Exactly five lowercase characters from `23456789abcdefghjkmnpqrstuvwxyz`, with configured prefix `a`, are accepted. Malformed/unknown-prefix paths redirect to `/` without an event. Codes are generated by CRM; Worker validates syntax/prefix, not existence in CRM (no lead registry here).
- `POST /t/e`: JSON `{ "code": "a2345", "type": "view" }`. Accepts `application/json`, `text/plain` (sendBeacon string), or an absent Content-Type; `application/json` Blob beacons also work. Six public types: `view`, `scroll_proof`, `cta_sms`, `cta_call`, `pdf`, `arbcut`; callers cannot insert `click`. Successful insert: `204`; invalid JSON/code/type: `400`; unsupported media type: `415`; body over 1 KiB: `413`; rate-limited: `429` + `Retry-After`; unavailable storage: `503`.
- Public beacons use a shared D1 per-code fixed window (60 accepted events/minute across all six types and all isolates). It is abuse mitigation, not identity verification: anyone knowing a code can fabricate a public beacon. Bot classification comes from request UA; no IP/full UA is stored. Same-origin beacons; no permissive CORS.
- Click logging/storage failure never changes the valid redirect. Invalid codes never store anything.

## CRM pull endpoint and cursor (coordinate before CRM implementation)

`GET /t/events?since=<ISO>&limit=500` requires `Authorization: Bearer <EVENTS_TOKEN>` (Worker secret). Missing/wrong credentials: `401`; missing server secret: `503`. `since` is required and must include a UTC offset or `Z`; it is normalized to UTC milliseconds. `limit` defaults to 500, integer 1–500. Invalid query/cursor: `400`. All responses are uncached.

```json
{
  "events": [
    { "id": "42", "code": "a2345", "type": "click", "at": "2026-10-11T13:00:00.000Z", "ua_class": "human" }
  ],
  "next_cursor": null,
  "has_more": false
}
```

IDs are persistent SQLite AUTOINCREMENT IDs encoded as decimal strings. Deduplicate by `(Worker database identity, id)`; never deduplicate on timestamps, which can be equal. Events are sorted ascending by `(at, id)` and initial `since` is **inclusive**.

When `has_more` is true, call with the **same `since`** and `cursor=<next_cursor>` (URL-encode it). The opaque versioned cursor contains a snapshot high-water ID and last `(at,id)`, preventing gaps at equal timestamps and preventing new arrivals from extending an in-progress page set. `next_cursor` is non-null only when another page exists. Commit each page's events and checkpoint together in CRM; retrying a page returns the same retained event IDs. A cursor is a paging token, not an authorization token.

After `has_more:false`, start the next poll with `since` equal to the largest ingested `at`, no cursor; boundary events are replayed and must be deduplicated by ID. Preserve the previous `since` on an empty pull. Late-arriving events inserted during paging are included on that next poll. Persist a page cursor only for unfinished paging. Never advance `since` to the pull request's wall-clock time: that could skip concurrent inserts. Persist nothing past a failed page. Timestamps are generated by D1, not supplied by public callers.

`ua_class` is `bot` for facebookexternalhit, WhatsApp, TelegramBot, Slackbot, Twitterbot, SkypeUriPreview, Googlebot, bingbot, Google-PageRenderer, or generic `bot|crawler|spider|preview` (case-insensitive), else `human`. A `click` alone is not a confirmed real view; CRM should mark proof viewed on a `view` beacon and retain the classifier.

## Retention and operations

Events expire after 12 calendar months in UTC (month-end clamps to the last day of the destination month). Request-time cleanup deletes expired events and expired rate-limit buckets, at most once per hour using a D1 lease. Pulls always exclude expired events even before deletion. No cron/scheduler is configured; physical deletion awaits the next handled request after expiry if the Worker is idle. Secrets, IPs, and full user agents are never logged or committed.
